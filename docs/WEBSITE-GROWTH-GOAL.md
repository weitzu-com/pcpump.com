# PCPUMP 建站目标与增长验收规格

制定日期：2026-10-17。状态：目标定义完成；数值为首轮规划假设，未取得业务基线，不是行业基准或效果承诺。

## 明确目标

将 www.pcpump.com 建成面向海外油田运营商、人工举升服务商及设备采购工程团队的技术获客网站。以附件支持的PCP人工举升产品为首期重点，采用已选DJI技术规格UI的信息结构，使客户能找到适合讨论的系统、理解型号与材料约束、提交可跟进的工程需求。

从“内容、询价接收和测量均完成上线验收”的T0开始，90天内累计产生至少15个经人工审核合格的独立工程询盘；其中至少5个进入双方技术澄清，至少2个进入正式报价。第61—90天目标为至少8个合格询盘，用于观察近期产出。后续稳定期以滚动30天产出衡量。

这组数值是明确的首轮挑战目标，依赖目标市场流量、内容索引、供货能力和销售跟进；第1—14天测量基线后可基于证据提议修订，保留原目标和变更理由，不能事后静默降低目标。报价与成交需销售和工程团队配合，网站交付本身不保证业务结果。

## 为什么这个目标成立

采购决策需要降低工况适配、配套兼容性及供应能力的不确定性。附件包含型号、排量、参考扬程、驱动参数、材料配方和制造检测信息，因此首要客户价值是“更快获得可讨论的配置路径及待补数据清单”。增长衡量应连接到客户价值与销售进展，而非只统计访问量和按钮点击。

采用增长黑客的北极星指标、漏斗诊断和持续实验方法；不机械套用SaaS日活、注册率或病毒传播。工业采购周期长，复访、工程澄清、报价和复购比频繁访问更有解释力。

## 北极星指标：合格工程询盘数

以滚动30天新增、经人工审核合格的独立“公司＋项目”需求计数；90天启动阶段另报告累计值。

合格必须同时满足：

1. 具备可核实的公司/组织信息及可联系的业务联系人；个人邮箱不自动判为无效。
2. 存在明确项目、设备替换、备件或系统需求，且属于已确认可服务范围。
3. 说明至少一个具体条件，例如目标流量、井况、介质、现有型号或采购规格；其他数据允许待补。
4. 销售/工程人工确认具备下一步跟进价值，记录审核人、日期及理由。

同公司同项目在90天观察期内补交资料或通过多渠道联系只计一次；不同项目可分别计数。排除垃圾、招聘、推销、内部测试及无明确需求的重复提交。待审核、待核实和不合格分别记录，不能以表单成功回执直接计入北极星指标。

“进入技术澄清”要求买卖双方已有实质技术交流或客户补充资料；仅销售发出邮件不算。“进入正式报价”要求已有面向该项目的正式报价记录，不能以内部草稿或按钮点击计数。

## 增长漏斗与记录

| 阶段 | 衡量方式 | 真值与改进方向 |
|---|---|---|
| 获客 | 非品牌搜索曝光/点击、按来源与落地页统计的访问 | GSC及分析平台；优先具体产品/问题页面，区分品牌和非品牌流量 |
| 激活 | 进入规格/材料区域、打开相关资料、开始询价的会话占比 | 匿名事件，仅作意向信号；检查客户是否找到有用信息 |
| 转化 | 后端成功接收的独立需求数/有分析记录的会话数 | 标注分析阻断及跨设备限制；提交按钮点击不能作分子 |
| 质量 | 合格数/已完成人工审核数，并报告待审数 | 审核台账；不能通过把困难需求长期留待审美化结果 |
| 推进 | 技术澄清数、正式报价数及对应转化率 | 同一需求ID回连销售记录；按询盘生成批次观察，说明成熟时间 |
| 留存/收入/转介绍 | 客户补充资料、复访、商机金额、成交及客户介绍 | 补充资料和销售记录为主；成交金额需真实记录，不预填增长率 |

示例匿名事件：spec_view、resource_open、inquiry_start。后端持久化成功后记录inquiry_received；lead_qualified、technical_discussion、quote_issued来自人工确认的业务记录。询价ID等标识先做最小化设计，不携带个人信息进入公开分析工具。来源无法可靠关联的需求标为unknown，不分摊伪造。

## 目标拆解与经济约束

示例测算：3,000个会话 × 1%成功接收需求率 × 50%合格率 = 15个合格询盘。三个数字都是待验证的规划假设；表单归因与人工去重会造成差异，测量时须统一统计范围。该公式用于找瓶颈，不能证明流量一定存在。

单位合格询盘成本 = 同期可归因获客支出/对应批次合格询盘数；合格询盘为0时报告“无合格产出，已支出X”，不填0成本。允许成本上限应由单笔贡献毛利、成交概率和可接受获客成本占比推导，现阶段均待补，不能据此自动开广告。

## 90天增长实验

| 阶段 | 交付与假设 | 判定方式 |
|---|---|---|
| T0前 | 产品证据、页面、询价接收、测量与审核台账验收 | 开发检查通过，并完成标记为测试的询价收件读回；测试排除出业务指标 |
| 第1—14天 | 建立流量与漏斗基线，访谈5位目标角色作为建议样本 | 观察是否能找到型号、理解单位和完成询价；记录问题，不视小样本为统计证明 |
| 第15—30天 | 上线PCP、驱动、橡胶/介质等高意图内容；假设具体问题内容比宽泛首页更能引出需求 | 按来源、页面和项目审核反馈观察，明确索引及样本限制 |
| 第31—60天 | 优先测试“先基本需求，再可选工况”的表单与“提交工况获取选型建议”的入口 | 同时看接收数、合格率和技术资料完整度；单次改一个核心因素 |
| 第61—90天 | 放大有证据的页面/来源，修复质量或跟进瓶颈 | 查看滚动30天合格数、90天累计与澄清/报价进度；未达成如实报告 |

每两周复盘一次，实验台账记录假设、变体、预先选定指标、流量范围、起止日期、样本、结果和下一步。流量不足时优先可用性观察和客户访谈；不凭几次点击宣布A/B显著，不随结果改分母，也不以降低资格标准制造增长。

## 建站验收与业务目标分开

建站验收：

- 访客能按系统或工况进入相关产品；PCP、ESPCP和ESP电机边界清晰。
- 核心参数带单位、参考条件、来源页码和待补信息；不把扬程当井深，不把电机指标当整机指标。
- 规格、材料、配套和资料入口在桌面与手机可用，主行动入口清晰，表格可读，键盘可操作。
- 询价验证输入、真实持久化并能读回，收件方收到完整摘要；重复提交可识别，失败有可恢复提示。
- 匿名事件在实际测量端可见，测试需求排除；SEO规范链接、索引、现有语言路由和适用构建检查通过。

增长验收：必须有上述合格询盘、双方技术交流及正式报价的实际记录。网站上线、部署READY、页面截图及表单HTTP成功均不能替代。
